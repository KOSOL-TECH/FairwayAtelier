## Architecture as it is now

```
Browser ─► Cloudflare (custom domains, www→apex 301, HTTPS)
          └► Worker (Astro 7 SSR, @astrojs/cloudflare)
               middleware.ts ── /admin/** guard (HMAC session cookie)
               pages/*.astro ── loadPage(DB, def) ─► D1 page_blocks (edits only; defaults in src/lib/pages/*.ts)
               pages/journal ── D1 articles ─► marked
               pages/availability, Departures (server island) ─► D1 weeks
               /media/[id] ── R2 original ─► IMAGES binding resize ─► edge cache (immutable)
               /api/enquiry ── validate → rate limit → sinks: Console → D1 → team email → guest email
               /admin/** ── weeks, enquiries, journal, media, pages, audit_log
          └► ASSETS (/_astro/* hashed, immutable)
```

- **Every route renders on demand.** All 26 page and endpoint files set `prerender = false`, so `output: 'static'` is in name only. The comments in `astro.config.mjs:5-6` and `src/middleware.ts:10` still say "every page is prerendered". They are stale.
- **Content model:** approved copy lives in code as defaults (`src/lib/pages/*.ts`, `definePage`). D1 stores only the diffs (`page_blocks`). Restoring a field means pasting the original back. This is a good design.
- **Data:** D1 holds 7 migrations (audit_log, admin_users, weeks, enquiries, media + articles, page_blocks, photography seed). R2 holds the media originals.
- **Conventions:**
  - Files: kebab-case in `lib/`, PascalCase for components.
  - Tests: `*.test.ts` next to the module.
  - Commits: plain-English subjects prefixed with the area ("Home hero: …", "Admin: … (T-xx)").
  - Workflow: straight to `main`; CI runs tests and the build, and Workers Builds deploys.

## Findings

Ranked by impact. Owner is Dev unless noted.

### High

| ID | Finding | Where | Fix |
|---|---|---|---|
| P-1 | **Public HTML has no `Cache-Control`.** Every view runs the Worker plus 1–2 D1 queries. This was confirmed live: the home page has no cache header. It costs TTFB, LCP, Worker requests and D1 reads compared with the prerendered pages audited on 2026-11-01. | `src/middleware.ts`, all public pages | Set `public, s-maxage=300, stale-while-revalidate=86400` on public GET 200 responses. Optionally use the Cache API and purge it from the admin save handlers so edits still show at once. |
| P-2 | **The 130 KB villa SVG is inlined into every home response.** It is about 80% of the 162 KB HTML and cannot be cached separately. | `src/pages/index.astro:15,43`, `src/assets/villa-banner.svg` | Serve it as a hashed static asset and reference it with `<use href="…#fav-villa">`, or optimise it with SVGO. The SVG is approved byte-for-byte (X-27), so check with the client before optimising. P-1 softens this either way. |
| R-1 | **A D1 failure takes down the whole marketing site.** `loadPage` has no fallback, although every default is in code. `c.img(...)!` turns a missing media row into a TypeError. | `src/lib/copy.ts:60`, `src/pages/index.astro:25` | Catch the error and fall back to `mergeBlocks(def, [])`. Handle a null image without the `!`. |
| R-2 | **An email failure after the D1 save returns 502, so the guest retries and creates duplicates.** The sinks run one after another (`handler.ts:44`). If the team email throws, the guest confirmation is skipped and the form says "could not send". | `src/lib/enquiry/handler.ts:42-46`, `src/pages/api/enquiry.ts:38-41` | Treat the D1 save as success. Send the emails with `Promise.allSettled` and log failures. Optionally add a `notify_failed` flag shown in the inbox. |

### Low

- **Fonts:** no preload for the hero/body faces, and 11 `@font-face` weights are loaded (`src/styles/fonts.css`). Preload Cormorant 500 and Montserrat 400, and drop unused weights.
- **Focus rings:** form fields use `outline:none` plus a box-shadow, which disappears in Windows High Contrast (`components.css:151,155`). Add a `forced-colors` rule.
- **Home cards:** the image alt duplicates the heading inside the same link (`index.astro:73`). Use `alt=""`.
- **Navigation landmarks:** there are two `<nav aria-label="Main">` (`Header.astro:14,23`). Rename the mobile one "Menu".
- **Login:** rate-limited per IP only, and sign-ins are not written to `audit_log` (`login.astro`).
- **Enquiry body size:** the body is parsed before any size check (`api/enquiry.ts:18`). Reject anything over about 16 KB.
- **Media uploads:** the client's `file.type` is trusted. Compare it with `IMAGES.info().format`.
- **Admin CSS:** `:global(blockquote)` inside `<style is:global>` is invalid (build warning), so the admin preview's blockquote style is dropped (`AdminLayout.astro:128`). Remove the `:global()`.
- **Article form:** `Number(x) || 0` for `sort_order` accepts `1e999` (Infinity) (`articles.ts`). Clamp it to an integer.
- **Page saves:** `mergeBlocks` uses the untrimmed default but `savePage` compares against the trimmed one (`copy.ts:56` vs `:100`). Trim both.
- **Dead code:** `src/components/ui/Card.tsx` and `Checkbox.tsx` have no importers.
- **Stale comments:** `astro.config.mjs:5-6`, `src/middleware.ts:10`, `Departures.astro`.
- **Dependencies:** apply the patch updates. Plan marked 18 and TS 7 as separate upgrades.

## Strengths

- **Type safety and validation:** strict TS with no `any` or `@ts-` ignores, and client and server share validation (`validateEnquiry`).
- **Queries:** every D1 query is parameterised, and the schema uses CHECK constraints.
- **Admin auth basics:**
  - PBKDF2 hashes with timing-safe comparison, plus a dummy hash against user enumeration.
  - `__Host-`, HttpOnly, Secure and SameSite=Strict cookie; Astro's origin check guards CSRF.
  - `safeNext` stops open redirects.
- **Media:** an allow-list of widths and formats caps the Images transformation cost, and resized media is cached as immutable.
- **Content model:** defaults live in code and D1 stores only the diffs, which makes "restore original" trivial and safe.
- **Accessibility basics:** skip link, labelled form with focus moved to the first error, native `<dialog>`, reduced-motion support, and consent buttons of equal weight.
- **Process:** BACKLOG.md discipline and the commit history make the project easy to pick up.
